Version 10 / 1.0.1 now includes the full animation extension. Read `CHANGELOG_ANIMATION_A.md` and inspect `/art-gallery.html`. New files live under `public/assets/animated/`; the original `pixel/` assets below remain intact.

Character sheets: 240×240, six columns × six rows, 40×40 cells. Rows in order: idle, walk, attack, cast, hit, defeat. Icons: 120×20, six 20×20 frames. Effects: 240×40, six 40×40 frames. The animation manifest maps every stable ID to its sheet. `animated-art.js` handles presentation and loading fallback; `animated-theme.css` handles pixel sampling and step animation.

# Art guide — Aetherboard Version 10

## Direction

Original 16-bit-era fantasy presentation: compact palettes, dark sprite outlines, hard pixel edges, mossy ruins, elemental stone floors and warm gold/teal menus. The inspiration is the visual vocabulary of SNES adventures such as *A Link to the Past*, not a redistribution of Nintendo's characters, tiles, logos or music.

These are original authored raster assets. The live game uses the PNGs and CSS in this repository, not a single flattened image of a game interface. The generative concept images discussed in chat are not shipped as fake functional UI. Actual rendered-client screenshots are in `docs/v10/screenshots/`.

## Inventory

| Directory | Contents | Source grid |
|---|---|---|
| `public/assets/pixel/units/` | 56 existing spirit IDs, one unique transparent PNG each | 32×32 |
| `public/assets/pixel/icons/` | 49 elemental, role, item and commander symbols | 20×20 |
| `public/assets/pixel/tiles/` | 18 floor variants, 4 hazards, pillars/void, 3 nodes | 32×32 |
| `public/assets/pixel/ui/` | 6 scenery strips; landscape, bitmap title, crest | Native dimensions vary |
| `public/assets/pixel/manifest.json` | ID-to-file mapping; art release metadata | Data only |

The title panorama shows five Fire spirits and one Water spirit to match the existing +40% Fire Bond example. Text labels are still live HTML. Existing hit targets and assistive labels identify the spirits; decorative images use empty alt text rather than duplicating names.

The main title lettering is an authored bitmap image, not a bundled font. Interface text uses system fonts for readability. No font files are distributed.

## Palettes and forms

Each element has a six-tone ramp. Forms include cats/foxes, fish, armored creatures, birds, dragons, insects, staves and healers, drums/banners, spirits and crystals. Similar species intentionally share visual motifs, but the 56 PNG files have distinct pixel content. Prices, classes, names and effectiveness are read from the unchanged shared catalog; this art release does not rebalance them.

Floor variants are fixed visual variations, not extra terrain generation. The active map key selects a palette. Hazards and buff nodes retain visible icon/text labels. Side trees, rocks and ruins stay outside the playable grid and never add collision.

## Your future custom assets

Set an existing stable spirit key in `CUSTOM_ASSETS.unitImages` inside `public/index.html`:

```js
unitImages: {
  cinderCub: "assets/your-art/cinder-cub.png",
  tideNurse: "assets/your-art/tide-nurse.png"
}
```

Configured custom images take priority. A broken custom URL falls back to the bundled sprite; failure of both falls back to the old placeholder. Keep your own art outside the generated `pixel/` folder.

Music still uses `CUSTOM_ASSETS.musicUrl`; blank uses the existing procedural soundtrack. Audio composition and gameplay timing were not changed.

## Rebuilding the original bundled assets

Normal players do **not** run this. The PNGs are already checked in.

For an artist/developer who deliberately edits the authoring geometry:

```sh
python -m pip install Pillow
python tools/build_pixel_art.py
```

Node must also be available: the authoring script reads the live shared catalog using Node. It writes the `pixel/` directory, manifest, pixel-art script and sprite-catalog image. It does not write shared rules, server files, custom overrides or saves. Its randomness is seeded at build time and completely separate from gameplay RNG.

Review the contact sheet at `docs/v10/sprite-catalog.png`. Run `npm test` and the optional browser art tests after rebuilding. The test suite checks IDs, dimensions, uniqueness, fallbacks, preserved files, delivered assets and layout boundaries.

## Technical reference

CSS image rendering uses pixel-preserving sampling, with no runtime smoothing or downloaded web font. See MDN's `image-rendering` reference: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/image-rendering . Scaling behavior can still vary slightly with browser/zoom/display density; this is a modern browser game, not a claim of exact original-console hardware emulation.
